# PulsarWeb — общая модель, продукт и техническая база

## 1. Что такое PulsarWeb

PulsarWeb — небольшая независимая web/software-студия, которая создаёт новые цифровые продукты для бизнеса с нуля и под ключ.

Основная модель работы:

```text
идея
→ проектирование
→ дизайн
→ разработка
→ интеграции
→ инфраструктура
→ production
→ запуск
```

Клиент покупает не отдельные технические работы, а готовый работающий продукт.

PulsarWeb не продаёт отдельно:

```text
дизайн
frontend
backend
database
VPS
Docker
SSL
deployment
```

Это внутренние составляющие проекта, за которые отвечает студия.

После запуска клиент может отдельно подключить платное техническое сопровождение.

```text
Разработка + запуск
= основной продукт

Сопровождение
= отдельная платная опция
```

## 2. Позиционирование

Основная формулировка:

> Разрабатываем цифровые продукты для бизнеса.

Дополнительная формулировка:

> От первой идеи до работающего продукта.

PulsarWeb не позиционируется как классическое digital-агентство, которое отдельно продаёт дизайн, разработку, рекламу и другие услуги.

Главная ценность студии:

- прямое общение с разработчиком;
- полный технический цикл;
- frontend и backend в одном контексте;
- базы данных;
- интеграции;
- Telegram;
- платежи;
- инфраструктура;
- deployment;
- production;
- последующее сопровождение.

## 3. Для кого PulsarWeb

Основная аудитория:

- малый бизнес;
- предприниматели;
- небольшие компании;
- небольшие команды;
- проекты, которым нужен новый цифровой продукт.

PulsarWeb особенно подходит клиентам, которые не хотят самостоятельно собирать:

```text
дизайнера
+
frontend-разработчика
+
backend-разработчика
+
DevOps
+
интегратора
```

Студия берёт ответственность за весь технический цикл.

## 4. Что PulsarWeb не делает

Основной фокус — создание новых продуктов.

Студия не позиционируется как сервис для:

- переделки чужих сайтов;
- исправления случайного чужого кода;
- редизайна существующих продуктов;
- поддержки чужих legacy-систем;
- мелких бессистемных доработок;
- постоянной работы с чужими техническими долгами.

Нестандартный новый software-проект при этом может быть принят.

## 10. Архитектурный подход

Для серьёзных проектов основной ориентир:

```text
modular monolith
```

Главное правило:

> Бизнес-логика не должна зависеть от Next.js, React или UI.

Типичный flow:

```text
Route Handler
→ Zod
→ Application Use Case
→ Repository
→ Database
```

Не писать бизнес-логику непосредственно в Route Handler.

Интеграции строятся через adapters.

Например:

```text
EmailProvider
→ ResendEmailProvider
```

```text
LeadNotificationProvider
→ TelegramNotificationProvider
```

## 12. Telegram как capability

Telegram может использоваться в web-проектах для operational-задач.

Например:

```text
новая заявка
новый заказ
оплата
изменение статуса
системное событие
```

могут приходить владельцу бизнеса в Telegram.

При необходимости Telegram может использоваться как лёгкий operational interface без тяжёлой CRM.

Telegram не должен добавляться в каждый проект автоматически.

- Docker;

- HTTPS;

- deployment;

- запуск.

Для клиента это часть готового продукта.

Default:

## 17. Основные продуктовые принципы

При принятии решений учитывать:

- пользу для клиента;
- понятность;
- стоимость разработки;
- поддерживаемость;
- будущую поддержку;
- масштабирование;
- стоимость инфраструктуры;
- потенциальное переиспользование.

Главный принцип:

```text
проще и достаточно
>
сложнее и универсальнее
```

До тех пор, пока реальная задача не требует усложнения.

## 18. Главная цель PulsarWeb

PulsarWeb не должен выглядеть как искусственно раздутое агентство.

Цель:

> Стать небольшой технически сильной студией с понятным продуктом, качественной разработкой и ответственностью за результат от первой идеи до production.
