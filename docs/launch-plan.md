# PulsarWeb — план запуска

## 1. Цель запуска

Первый запуск PulsarWeb — не масштабирование студии.

Главная задача:

> Проверить, существует ли реальный спрос на предложение PulsarWeb и можно ли получать качественные заявки по экономически приемлемой цене.

Первый запуск рассматривается как controlled experiment.

Не нужно ожидать, что первая рекламная кампания сразу построит стабильный бизнес.

## 2. Ограничения

PulsarWeb запускается с небольшим личным бюджетом.

Поэтому основной принцип:

```text
не распылять деньги
```

Первый рекламный бюджет должен использоваться для получения данных и первых клиентов, а не для охвата максимального количества каналов.

## 3. Что необходимо завершить до запуска

Лендинг доводится до полноценного production-ready состояния.

Перед рекламой должны работать:

```text
главная страница
услуги
цены
кейсы
/start
lead storage
Telegram notification
analytics
UTM
production deployment
```

Особое внимание:

```text
реклама
→ landing page
→ /start
→ submit
→ database
→ notification
```

Этот flow необходимо протестировать вручную до запуска кампаний.

## 4. Первый case study

До активного запуска рекламы желательно оформить:

```text
Pulsar VPN
```

Он является proof of execution.

Кейс должен показать:

```text
идея
→ архитектура
→ frontend
→ backend
→ integrations
→ infrastructure
→ production
```

## 5. Стартовые цены

На момент первого запуска:

```text
Лендинги под рекламу
от 25 000 ₽

Корпоративные сайты
от 45 000 ₽

Интернет-магазины
от 70 000 ₽

Telegram-боты
от 20 000 ₽

Telegram Mini Apps
от 40 000 ₽

Другой проект
индивидуальная оценка
```

Цены пересматриваются после первых реальных проектов.

Повышение происходит не по календарю, а по фактическим сигналам:

- появились кейсы;
- появились отзывы;
- выросло качество продукта;
- увеличился спрос;
- появилась загрузка;
- стало понятно фактическое количество часов на проект.

## 6. Главный рекламный канал

Первый приоритет:

```text
Яндекс Директ
```

Причина — возможность работать со сформированным поисковым спросом.

Примеры intent:

```text
заказать лендинг
разработка лендинга
создание корпоративного сайта
разработка интернет магазина
разработка telegram mini app
telegram бот для бизнеса
```

Не рекламировать всё одним универсальным объявлением.

## 7. Структура рекламы в Яндексе

Рекламу желательно разбивать по продуктам.

Например:

```text
landing_search
corporate_search
ecommerce_search
telegram_search
```

Каждая кампания должна вести на релевантную страницу.

Пример:

```text
"разработка интернет-магазина"
→ /services/ecommerce
```

а не обязательно на главную.

## 8. Промокод Яндекс Директа

Для первого запуска рассматривается промокод:

```text
15 000 ₽ собственных средств
+
30 000 ₽ бонус
=
45 000 ₽ рекламного бюджета
```

Перед использованием необходимо ещё раз проверить действующие условия акции в момент запуска.

Поскольку личный бюджет ограничен, не увеличивать рекламные расходы только ради получения большего бонуса.

## 9. Второй канал — Авито

Авито использовать как дополнительный недорогой тест.

Не создавать одно универсальное объявление:

```text
Разработка сайтов
```

Лучше отдельные предложения:

```text
Лендинг для рекламы под ключ

Корпоративный сайт для бизнеса

Интернет-магазин с оплатой

Telegram-бот для бизнеса
```

Авито используется не только как источник клиентов, но и как источник market feedback.

Фиксировать:

- что спрашивают;
- какие бюджеты называют;
- какие возражения возникают;
- какие услуги вызывают интерес;
- какие формулировки понятны клиентам.

## 10. VK Ads

VK Ads не является первым приоритетом.

Причина:

```text
Яндекс
→ существующий intent

VK
→ необходимо сначала создать интерес
```

VK лучше тестировать после:

- появления нескольких кейсов;
- появления понятного offer;
- понимания основной аудитории;
- подготовки контента.

В дальнейшем VK можно использовать для:

- кейсов;
- ретаргетинга;
- контентной рекламы;
- предпринимательской аудитории.

## 11. UTM strategy

Использовать единый naming convention.

### Яндекс

```text
utm_source=yandex
utm_medium=cpc
utm_campaign=landing_search
utm_content=ad_01
```

### VK

```text
utm_source=vk
utm_medium=paid_social
utm_campaign=landing_business
utm_content=creative_01
```

### Авито

```text
utm_source=avito
utm_medium=classified
utm_campaign=landing
utm_content=listing_01
```

При необходимости:

```text
utm_term
```

используется для keyword/search term.

## 12. Attribution

UTM должны не только попадать в Метрику.

Они должны сохраняться непосредственно с lead.

Минимально:

```text
utmSource
utmMedium
utmCampaign
utmContent
utmTerm

landingPage
referrer
createdAt
```

В дальнейшем можно добавить:

```text
leadStatus
qualifiedAt
wonAt
revenue
```

Это позволит считать не только заявки, но и реальные продажи по источникам.

## 13. Основная воронка

Отслеживать:

```text
impression
↓
click
↓
landing visit
↓
start opened
↓
start begun
↓
start completed
↓
qualified lead
↓
conversation
↓
proposal
↓
won
```

Главные показатели первой итерации:

- CTR;
- CPC;
- количество посещений;
- conversion landing → lead;
- стоимость lead;
- количество qualified leads;
- стоимость qualified lead;
- количество переговоров;
- количество продаж;
- revenue by source.

## 14. Что считать хорошим результатом

Не оценивать эксперимент только по количеству клиентов.

Например:

```text
15 000 ₽ собственных средств
→ рекламный бюджет 45 000 ₽
→ 10–15 нормальных лидов
→ несколько переговоров
→ 1 клиент
```

может быть сильным результатом.

Даже отсутствие сделки не означает автоматически отсутствие спроса.

Необходимо определить, где именно возникает проблема:

```text
нет кликов
→ реклама

есть клики, нет заявок
→ landing / offer

есть заявки, но они плохие
→ targeting / pricing / positioning

есть хорошие заявки, нет продаж
→ trust / proposal / sales process

есть продажи, но проект убыточен
→ pricing / scope
```

## 15. Финансовый принцип

До доказательства работающей модели не увеличивать расходы резко.

Первый этап:

```text
Яндекс Директ
+
Авито
```

VK и дополнительные каналы подключаются после анализа первых результатов.

Не использовать одновременно большое количество рекламных площадок при маленьком бюджете.

## 16. Первые клиенты

Главная задача первых проектов:

```text
деньги
+
опыт
+
реальный production
+
отзыв
+
case study
+
понимание экономики
```

После каждого проекта фиксировать:

- итоговую стоимость;
- количество затраченных часов;
- дополнительные правки;
- сложность коммуникации;
- фактическую маржу;
- что можно стандартизировать;
- что можно добавить в pulsar-starter.

## 17. Как повышать цены

Не использовать модель:

```text
через 3 месяца цена автоматически x2
```

Использовать постепенное повышение.

Пример:

```text
первые проекты
25k

появились кейсы
35k

появился стабильный спрос
45–50k+

появилась загрузка
дальнейшее повышение
```

Аналогично для других продуктов.

## 18. Что не нужно делать до первого запуска

Не откладывать запуск ради:

- универсальной CMS;
- собственной CRM;
- клиентского кабинета;
- сложного billing;
- Kubernetes;
- большой internal platform;
- десятков интеграций;
- огромного design system;
- блога на сотни страниц;
- идеального starter template.

Сначала необходимо подтвердить:

```text
люди готовы платить PulsarWeb
```

## 20. Главный принцип запуска

PulsarWeb не должен ждать состояния:

```text
идеально готово
```

Но реклама должна запускаться только тогда, когда основной customer journey уже профессионально работает.

Цель первой версии:

> Не построить идеальную студию, а получить первые реальные доказательства того, что рынок готов покупать продукт PulsarWeb.
