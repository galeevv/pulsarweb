# SEO PulsarWeb и референса — 21 октября 2026

## Границы проверки

PulsarWeb проверен по актуальному исходному коду в `D:/Web3/pulsarweb` и тестовой production-сборке. Публичный домен не указан. Референс проверен прямым HTTP-чтением HTML, robots.txt и sitemap.xml. Поисковые позиции, трафик, ссылки и полевые Core Web Vitals не измерялись; доступа к Search Console / Яндекс Вебмастеру нет. Это технический и контентный обзор, а не оценка эффективности продвижения.

## PulsarWeb

Что уже сделано:

- Серверный HTML и статическая генерация маркетинговых страниц; поисковику не требуется выполнять клиентский код, чтобы получить основные тексты.
- Собственные страницы четырёх продуктов, отдельные title/description, canonical и Open Graph / Twitter metadata.
- Автоматические sitemap.xml и robots.txt, `lang="ru"`, WebSite JSON-LD, общая социальная обложка.
- Юридические черновики и неопубликованный кейс закрыты `noindex` и исключены из sitemap. Для отсутствующих страниц предусмотрен настоящий 404.
- После смены услуг: старый `/services/websites` перенаправляется 308 на лендинги; инфраструктура — на каталог. Desktop и Web-системы сохранены как вторичные страницы с `noindex`, исключены из sitemap. Новые URL присутствуют в sitemap.

Что требует следующего этапа:

1. **Публичный адрес.** В проверенных локальных env-файлах SITE_URL не задан; значение по умолчанию — localhost. Для локальной разработки это нормально. До production нужно задать реальный HTTPS-origin при сборке и запуске, затем проверить canonical, sitemap, OG URL и редиректы домена. Настройки хостинга здесь не проверялись.
2. **Главная.** Title сейчас только `PulsarWeb` — это ранее выбранное оформление вкладки, а не ошибка генерации. Для небрандового поиска можно рассмотреть более предметный title. Общее description ещё упоминает старые web-системы: оно оставлено до следующего этапа по просьбе владельца.
3. **Доказательства опыта.** Реальные кейсы, скриншоты, описание задач, решений и подтверждённых результатов пока важнее добавления новых технических тегов. Неподтверждённые цифры публиковать не следует.
4. **Компания и контакты.** Нет фактической почты и заполненных реквизитов. После получения данных можно дополнить страницу студии и разметку Organization / ProfessionalService. Не подставлять вымышленные адреса или рейтинг.
5. **Измерение результата.** Упоминание Яндекс Метрики в стеке не означает установленный счётчик. В проверенном исходном коде рабочая интеграция аналитики не найдена. Подключение аналитики и цели успешной заявки — отдельная задача.
6. **Производительность.** Анимированный hero и изображения стоит измерить на production на мобильной сети. По виду страницы или dev-предупреждению LCP нельзя честно выставить оценку скорости.

## Референс

На [главной Yudaev](https://new.yudaevbranding.com/) сервер отдаёт HTML с одним H1, предметными title/description, canonical, OG-обложкой и JSON-LD типа ProfessionalService. В HTML найдена интеграция Яндекс Метрики; это не доказывает корректность целей. Запрета индексации в проверенном ответе не обнаружено. Дублируется `twitter:card` — небольшая техническая избыточность.

[Robots.txt](https://new.yudaevbranding.com/robots.txt) разрешает обход, исключает API и содержит Clean-param для рекламных параметров. [Sitemap](https://new.yudaevbranding.com/sitemap.xml) содержит только главную. Основные ссылки на услуги и кейсы ведут к якорям: в проверенной структуре нет отдельных коммерческих страниц под каждый продукт.

Сильная сторона референса — конкретное предложение, цены, кейсы, отзывы и ответы на возражения. Это полезный ориентир для содержания и конверсии. Одностраничная структура ограничивает возможность подробно раскрыть разные услуги по отдельным адресам; многостраничную структуру PulsarWeb стоит сохранить. Фактическое преимущество в поисковой выдаче по этой проверке установить нельзя.

## Порядок следующего этапа

1. Согласовать первый экран, общее описание студии и тексты вне каталога под новое позиционирование.
2. Подготовить реальные кейсы, контакты, условия работы и границы сопровождения.
3. Определить домен и целевую географию; согласовать поисковые темы для каждой услуги.
4. Настроить production metadata, аналитические цели и панели поисковых систем.
5. После публикации измерить скорость и проверить индексирование.

Услуги уже выделены в самостоятельные страницы; переносить чужую одностраничную структуру ради визуального сходства не требуется. Дизайн референса не является доказательством качества SEO. Общие принципы работы с полезным содержанием, адресами и индексацией описаны в [руководстве Google Search Central](https://developers.google.com/search/docs/fundamentals/seo-starter-guide).
