# PulsarWeb — лендинг студии

## 1. Цель лендинга

Главная задача сайта PulsarWeb — не демонстрация технологий.

Сайт должен приводить потенциального клиента к пониманию:

```text
что делает PulsarWeb
↓
подходит ли это под мою задачу
↓
почему студии можно доверять
↓
примерно сколько это стоит
↓
как начать проект
```

Главный conversion action:

```text
/start
```

## 2. Основное позиционирование

Главный message:

> Разрабатываем цифровые продукты для бизнеса.

Дополнительная формулировка:

> От первой идеи до работающего продукта.

Смысл должен быть понятен человеку без технического опыта.

Потенциальное раскрытие:

> Сайты, интернет-магазины и Telegram-продукты — от проектирования и разработки до интеграций и запуска в production.

## 3. Тон коммуникации

Тон:

- спокойный;
- уверенный;
- профессиональный;
- технически компетентный;
- без агрессивных продаж;
- без попыток выглядеть огромным агентством.

Не использовать избыточный маркетинговый язык:

```text
революционные решения
лучшие на рынке
увеличим продажи в 10 раз
гарантируем миллионы
```

PulsarWeb должен продавать себя через ясность, качество и ответственность за результат.

## 4. Визуальный стиль

Visual direction:

```text
premium minimalism
Apple-like
shadcn
clean
flat
modern
```

Основные характеристики:

- сильная типографика;
- много свободного пространства;
- аккуратная сетка;
- минималистичные изображения;
- restrained Motion;
- качественные детали интерфейса;
- отсутствие визуального шума.

Не использовать:

- aggressive gradients;
- neon;
- excessive glassmorphism;
- большие glow;
- случайные 3D-объекты;
- перегруженные decorative sections;
- generic SaaS visuals.

## 6. Hero

Hero должен мгновенно объяснять:

- что делает PulsarWeb;
- для кого;
- какой результат получает клиент.

Основной заголовок:

> Разрабатываем цифровые продукты для бизнеса.

Подзаголовок должен конкретизировать:

- сайты;
- интернет-магазины;
- Telegram;
- разработку под ключ;
- запуск.

Главный CTA:

> Обсудить проект

или:

> Начать проект

CTA ведёт на:

```text
/start
```

Возможен secondary action:

> Посмотреть проекты

## 8. Цена

На сайте использовать формат:

```text
от X ₽
```

Финальная стоимость зависит от:

- объёма;
- функциональности;
- интеграций;
- business logic;
- количества уникальных экранов;
- инфраструктурных требований.

Не писать публично:

```text
цена только на первые несколько месяцев
```

Цена должна повышаться постепенно по мере:

- появления кейсов;
- роста спроса;
- загрузки;
- опыта;
- улучшения позиционирования.

## 9. Почему PulsarWeb

Главное преимущество — не конкретный стек.

Клиенту нужно объяснить:

### Прямое взаимодействие

Клиент взаимодействует непосредственно с человеком, который проектирует и разрабатывает продукт.

### Один технический контекст

Frontend, backend, database, integrations и infrastructure не разбиваются между случайными исполнителями.

### Работа под ключ

PulsarWeb отвечает за путь:

```text
идея
→ проектирование
→ разработка
→ production
```

### Технологии выбираются под задачу

Клиент не обязан самостоятельно выбирать:

```text
database
VPS
Docker
backend
framework
```

Это ответственность студии.

## 10. Процесс работы

Основной универсальный процесс:

```text
Задача
→ Проектирование
→ Дизайн
→ Разработка
→ Интеграции
→ Запуск
```

Можно добавить пояснение:

> Конкретный состав этапов зависит от проекта.

Не нужно делать процесс искусственно длинным.

## 11. Снижение риска для клиента

На сайте важно показать, что покупка проекта контролируема.

Потенциальная модель:

```text
обсуждаем задачу
↓
фиксируем объём проекта
↓
согласовываем стоимость и сроки
↓
разбиваем работу на этапы
↓
показываем промежуточный результат
↓
запускаем production
```

Не обещать рискованные гарантии, которые сложно выполнить.

## 13. Founder-led модель

Не создавать впечатление несуществующей большой команды.

Можно спокойно объяснять:

> PulsarWeb — независимая web/software-студия.

Ключевая мысль:

> Прямое взаимодействие с разработчиком на протяжении всего проекта.

Не обязательно акцентировать формулировку:

> Я работаю один.

Важно показать преимущество модели, а не размер бизнеса.

## 14. Технологии

Стек можно показывать, но он не должен быть центром лендинга.

Технологии — secondary proof.

Например:

```text
Next.js
TypeScript
React
PostgreSQL
Prisma
Telegram
Docker
```

Клиент должен сначала понять бизнес-результат.

## 15. Start Project

Страница:

```text
/start
```

является главным conversion mechanism сайта.

Основной flow:

```text
тип проекта
→ описание задачи
→ бюджет и срок
→ контакты
→ review
→ submit
```

Категории:

```text
landing-pages
corporate-websites
ecommerce
telegram
support
other
```

Форма не должна превращаться в технический бриф.

Не спрашивать клиента:

```text
какая БД нужна
нужен ли Docker
какой backend
какой VPS
```

Клиент описывает бизнес-задачу.

Технический подход определяет PulsarWeb.

## 16. Lead storage

Заявка сначала сохраняется в database.

После успешного сохранения отправляется Telegram notification.

Flow:

```text
Lead submitted
↓
validate
↓
save to database
↓
return success
↓
send secondary notifications
```

Telegram не должен быть критической зависимостью.

Если Telegram недоступен, заявка не должна потеряться.

## 17. Analytics

До запуска рекламы необходимо подключить:

```text
Яндекс Метрика
UTM
conversion events
lead attribution
```

Желательно сохранять вместе с lead:

```text
utmSource
utmMedium
utmCampaign
utmContent
utmTerm

landingPage
referrer
createdAt
```

Пример:

```text
utm_source=yandex
utm_medium=cpc
utm_campaign=landing_search
utm_content=ad_01
```

Это позволит связывать рекламный источник с реальной заявкой и продажей.

## 18. SEO foundation

До запуска:

- корректные title;
- description;
- Open Graph;
- canonical;
- robots.txt;
- sitemap.xml;
- semantic HTML;
- правильная heading hierarchy;
- доступные формы;
- оптимизированные изображения;
- Core Web Vitals без явных проблем.

SEO не является главным каналом первой итерации, но техническая база должна быть корректной.

## 20. Главный принцип

Сайт PulsarWeb должен отвечать не на вопрос:

> Насколько технически сложную систему мы можем построить?

А на вопрос клиента:

> Можете ли вы взять мою задачу и довести её до работающего результата?
